## 들어가기 전에: 이 부록의 약속

이 강의는 C 를 **완벽하게 가르치지 않습니다.** 우리 목표는 딱 하나예요.

> **강의 실습 코드(`syscall_count.c`, `workload.c`, `tcpconnect.c`)에 실제로 나오는 문법만** 골라서, 코드를 보고 "아 이건 이런 뜻이구나" 하고 **읽을 수 있게** 만드는 것.

그래서 여기 없는 C 문법은 일부러 뺐습니다. 여기 있는 것만 알면 9·10주차 코드는 충분히 따라옵니다.

> [!TIP]
> **C 가 파이썬과 다른 점 한 줄 요약**
> 파이썬은 "적으면 바로 실행", C 는 "**먼저 기계어로 번역(컴파일)한 뒤 실행**". 그리고 C 는 **메모리(컴퓨터 안의 사물함)를 직접 다룬다**는 점이 가장 큰 차이입니다. 그래서 타입·크기·포인터 같은 개념이 등장합니다.

## 1. 변수와 타입 — "이 상자에 무엇을, 몇 칸 크기로 담을까"

파이썬은 변수를 만들 때 타입(종류)을 안 적습니다. C 는 **반드시 종류를 먼저 적어야** 해요.

```python
# 파이썬
x = 3          # 그냥 담으면 끝
name = "hello" # 종류를 안 적어도 됨
```

```c
// C
int x = 3;        // x 는 "정수(int)" 상자다, 라고 미리 선언
u32 tgid = 100;   // u32 = 부호 없는 32비트 정수
```

### 왜 "크기"를 신경 쓰나?

파이썬은 숫자 크기를 알아서 처리하지만, **커널은 메모리를 바이트(byte) 단위로 정확히 다뤄야** 합니다. 그래서 "이 값은 몇 바이트짜리다"를 타입으로 못 박습니다.

| 타입 | 크기 | 뜻 | 담을 수 있는 범위(대략) |
|------|------|----|----|
| `u32` | **4바이트 = 32비트** | unsigned 32-bit (부호 없는 정수) | 0 ~ 약 42억 |
| `u64` | **8바이트 = 64비트** | unsigned 64-bit (부호 없는 정수) | 0 ~ 약 1844경 |
| `u16` | **2바이트 = 16비트** | unsigned 16-bit | 0 ~ 65535 |
| `int` | 보통 4바이트 | 부호 있는 정수 (음수 가능) | 약 -21억 ~ +21억 |
| `long` | 보통 8바이트(리눅스 64비트) | 부호 있는 큰 정수 | 매우 큼 |
| `char` | 1바이트 | 문자 한 글자 / 작은 정수 | — |

> [!WARNING]
> **흔한 착각 주의:** `u64` 는 "8비트"가 아니라 **8바이트 = 64비트**입니다. (1바이트 = 8비트)
> 이름 속 숫자(32, 64)는 **비트 수**, 크기를 바이트로 말할 땐 그걸 8로 나눕니다. `u32` = 32비트 = 4바이트.

**"부호 없는(unsigned)"** 이란? 음수를 안 쓰는 대신, 그만큼 더 큰 양수까지 담는다는 뜻입니다. PID나 주소처럼 "음수가 나올 일 없는 값"에 씁니다.

> 👉 **강의에서:** 9주차 `syscall_count.c` 의 `u32 tgid`, `u64 id`, 10주차 `tcpconnect.c` 의 `u16 dport`(포트는 0~65535라 16비트면 충분) 에서 그대로 나옵니다.

## 2. 세미콜론·중괄호·컴파일 — "문장 끝엔 `;`, 묶음은 `{}`"

파이썬은 **들여쓰기**로 코드 묶음을 표현하고 줄바꿈으로 문장을 끝냅니다.
C 는 **`;`(세미콜론)으로 문장을 끝내고, `{ }`(중괄호)로 묶음**을 표현합니다. 들여쓰기는 사람 보기 좋으라고 할 뿐, 의미는 없어요.

```python
# 파이썬: 들여쓰기가 곧 묶음
if want == 0:
    return
```

```c
// C: 끝마다 ; , 묶음은 { }
if (want == 0) {
    return 0;
}
```

### 파이썬은 바로 실행, C 는 "번역 먼저"

```
파이썬:  소스코드 ──▶ (바로) 실행

C:      소스코드 ──[ 컴파일: 기계어로 번역 ]──▶ 실행파일 ──▶ 실행
```

C 는 사람이 쓴 글자(소스)를 컴퓨터가 바로 못 읽어요. **컴파일러**라는 번역기가 먼저 0과 1의 기계어로 바꿔 줘야 실행됩니다. (eBPF 에서는 BCC 라는 도구가 이 번역을 대신 해 줍니다 — 8주차 내용.)

> 👉 **강의에서:** 모든 실습 `.c` 파일이 `;` 와 `{}` 로 되어 있고, 8주차에서 BCC 가 이 코드를 컴파일해 커널에 넣는 과정을 배웁니다.

## 3. 포인터 (가장 중요!) — "값"이 아니라 "값이 있는 주소"

이게 C 에서 제일 낯설지만, eBPF 코드의 핵심입니다. 천천히 갑시다.

### 비유: 메모리는 "번호 붙은 사물함"

컴퓨터의 메모리는 **번호가 매겨진 사물함들**이라고 생각하세요. 각 사물함에 값이 들어 있고, 사물함마다 고유한 **번호(= 주소)** 가 있어요.

```
메모리(사물함들):
 주소: 1000     1004      1008
      ┌─────┐  ┌─────┐  ┌─────┐
      │ 100 │  │  7  │  │ ... │
      └─────┘  └─────┘  └─────┘
        ▲
        x 라는 변수는 1000번 사물함, 값은 100
```

- `&x` → **x의 주소** (x가 들어있는 사물함 번호 = "x네 집 주소"). 위 그림에서 `&x` 는 `1000`.
- `*p` → **그 주소로 찾아가서 값을 보기** ("집 주소를 들고 그 집에 찾아가 안을 들여다보기").

### 포인터 변수

"값을 가리키는 주소"를 담는 변수를 **포인터**라 하고, 타입에 `*` 를 붙입니다.

```c
u64 *val;   // val 은 "u64 값이 있는 주소"를 담는 포인터
```

화살표로 그리면:

```mermaid
flowchart LR
    val["val (포인터)<br/>값: 1004"] -->|"*val 로 따라감"| box["1004번 사물함<br/>값: 7"]
```

- `val` 자체는 **주소**(1004).
- `*val` 은 그 주소에 찾아가 본 **값**(7).
- `(*val)++` 는 "그 주소에 찾아가서, 거기 있는 값을 **1 증가**" → 7이 8이 됨.
  (`++` 는 "1 더하기". `(*val)++` 는 파이썬의 `box += 1` 과 같은 효과.)

```c
u64 *val = counts.lookup_or_try_init(&key, &init);  // 맵에서 값의 주소를 받아옴
if (val) {        // 주소가 유효하면 (아래 NULL 설명)
    (*val)++;     // 그 주소가 가리키는 값을 1 증가 = "카운트 +1"
}
```

### NULL 검사 — "빈 주소면 절대 들어가지 마"

가끔 "가리키는 곳이 없음"을 뜻하는 빈 주소가 있는데, 이걸 **NULL**(값으로는 0) 이라 합니다. 집 주소가 빈칸인데 그 집에 찾아가면? **프로그램이 터집니다(크래시).**

그래서 포인터를 쓰기 전에 **"빈 주소 아니지?"를 먼저 확인**합니다.

```c
if (!val) {       // !val = "val 이 NULL(빈 주소) 이면"
    return 0;     // 그럼 그냥 빠져나간다 (위험 회피)
}
// 여기 왔다면 val 은 유효한 주소 → 안전하게 *val 사용 가능
```

`!` 는 "아니다(NOT)". `if (!val)` 은 "val 이 비어있으면". `if (val)` 은 "val 이 (비어있지 않고) 유효하면".

> 👉 **강의에서:** 9주차 `syscall_count.c` 의 `u64 *val`, `(*val)++`, `if (!want || ...)`, `if (val)`. 10주차 `tcpconnect.c` 에서 `&family`, `&e.daddr` 처럼 `&`(주소)를 헬퍼 함수에 넘기는 장면이 계속 나옵니다.

## 4. 구조체(struct) — "여러 값을 묶은 상자"

관련된 값 여러 개를 **하나로 묶고 싶을 때** `struct` 를 씁니다. 파이썬의 딕셔너리나 간단한 클래스와 비슷해요.

```python
# 파이썬: 딕셔너리로 묶기
key = {"tgid": 100, "syscall_id": 39}
print(key["tgid"])     # 대괄호로 꺼냄
```

```c
// C: struct 로 묶기
struct key_t {
    u32 tgid;        // 멤버 1
    u32 syscall_id;  // 멤버 2
};                   // <- struct 정의 끝엔 ; 가 붙어요

struct key_t key = {};   // {} = 모든 멤버를 0 으로 초기화
key.tgid = 100;          // 점(.) 으로 멤버에 접근
key.syscall_id = 39;
```

- `struct key_t { ... };` → "tgid 와 syscall_id 를 묶은 새 상자 모양"을 정의.
- `struct key_t key = {};` → 그 모양의 상자 `key` 를 만들고 **전부 0으로** 채움.
- `key.tgid` → 점(`.`)으로 상자 안의 멤버를 꺼내거나 넣음 (파이썬 `key["tgid"]` 와 비슷).

### 메모리에 차곡차곡 쌓이는 그림

struct 의 멤버들은 메모리 사물함에 **순서대로 나란히** 놓입니다.

```
struct key_t key:
  ┌──────────────┬──────────────┐
  │ tgid (4바이트) │ syscall_id(4바이트) │
  └──────────────┴──────────────┘
   ◀──────────  합쳐서 8바이트  ──────────▶
```

> 👉 **강의에서:** 9주차 `struct key_t`, `struct comm_t`, 10주차 `struct event_t e = {};` / `e.pid = ...`. eBPF "맵(map)"의 키와 값으로 struct 가 자주 쓰입니다(8주차).

## 5. 비트·16진수·비트시프트 — "64비트 안에 32비트 두 개"

### 비트와 바이트

- **비트(bit)** = 0 또는 1, 컴퓨터의 가장 작은 정보 단위.
- **바이트(byte)** = 비트 8개 묶음. (그래서 32비트 = 4바이트)
- `u64` 값은 **0과 1이 64개** 늘어선 것입니다.

### 16진수(hex)

비트가 너무 많아 읽기 힘드니, 4비트씩 묶어 `0`~`9`,`A`~`F` 한 글자로 적는 게 **16진수**입니다. 앞에 `0x` 를 붙여요.

- `0xFF` = 11111111 (8비트 전부 1) = 십진수 255
- `0xFFFFFFFF` = 1이 32개 = **32비트 전부 1** = 약 42억. (강의 코드에서 "전체 추적"을 뜻하는 특별값으로 씀.)

### 비트시프트 `>>` — "오른쪽으로 밀기"

`id >> 32` 는 "비트들을 **오른쪽으로 32칸 밀어라**"는 뜻입니다. 그러면 **위쪽(상위) 32비트만 아래로 내려와 남습니다.**

리눅스 커널은 PID 정보를 64비트 한 덩어리에 **두 개의 32비트 값**으로 욱여넣어 줍니다:

```
bpf_get_current_pid_tgid() 가 주는 64비트:

  ┌────────────────────────┬────────────────────────┐
  │   상위 32비트 = TGID    │   하위 32비트 = PID     │
  │   (우리가 원하는 값)     │   (스레드 ID)           │
  └────────────────────────┴────────────────────────┘
   63                                                0

      │  >> 32  (오른쪽으로 32칸 밀기)
      ▼
  ┌────────────────────────┬────────────────────────┐
  │      전부 0 으로 채워짐  │   상위 32비트가 내려옴 = TGID │
  └────────────────────────┴────────────────────────┘
```

```c
u64 id = bpf_get_current_pid_tgid();  // 64비트: [TGID | PID]
u32 tgid = id >> 32;                  // 위쪽 32비트(TGID)만 꺼내기
```

> 즉 `>> 32` 는 **"64비트 두 칸 중 위쪽 칸만 떼어내는 기술"** 입니다.

> 👉 **강의에서:** 9주차 `syscall_count.c` 의 `u32 tgid = id >> 32;`, 10주차 `tcpconnect.c` 의 `e.pid = bpf_get_current_pid_tgid() >> 32;`. eBPF 에서 "현재 프로세스 ID 알아내기"의 정석 관용구입니다.

## 6. 타입 캐스팅 — "같은 메모리를 다른 안경으로 보기"

`(어떤타입)값` 은 "이 값을 **이 타입으로 해석하라**"는 뜻입니다. 특히 포인터에서, **같은 메모리 사물함을 다른 모양으로 다시 보는** 데 씁니다.

```c
struct sockaddr_in *sin = (struct sockaddr_in *)uaddr;
//                         └──── 이 주소를 sockaddr_in 모양으로 해석하라 ────┘
```

비유: 똑같은 메모리(번지 주소)인데, `uaddr` 은 "일반 주소"라는 **흐릿한 안경**으로 보던 것을, `(struct sockaddr_in *)` 라는 **선명한 안경**으로 바꿔 쓰면 그 안의 `sin_family`, `sin_port`, `sin_addr` 같은 세부 항목이 보입니다. **메모리 내용은 그대로, 보는 틀만 바뀝니다.**

```
같은 메모리 한 덩어리:  [ ... 바이트들 ... ]
   uaddr 안경:        "그냥 주소" (안이 안 보임)
   (sockaddr_in*) 안경: [ sin_family | sin_port | sin_addr | ... ]  ← 항목이 보임!
```

```c
// 캐스팅 덕분에 sin->... 으로 내부 멤버에 접근 가능
bpf_probe_read_kernel(&family, sizeof(family), &sin->sin_family);
```

> [!NOTE]
> 포인터로 멤버에 접근할 땐 점(`.`)이 아니라 **화살표(`->`)** 를 씁니다. `sin->sin_family` 는 "sin 이 가리키는 struct 의 sin_family 멤버" 라는 뜻 (= `(*sin).sin_family` 의 줄임).

> 👉 **강의에서:** 10주차 `tcpconnect.c` 의 `(struct sockaddr_in *)uaddr`. 커널이 넘겨준 주소를 "구체적인 주소 구조체"로 해석해 목적지 IP/포트를 읽어냅니다.

## 7. 함수 시그니처 읽는 법 — "반환형 / 이름 / 인자들"로 쪼개기

C 함수의 첫 줄(시그니처)은 **세 부분**으로 읽으면 됩니다.

```c
int kprobe__tcp_v4_connect(struct pt_regs *ctx, void *sk,
                           struct sockaddr *uaddr, int addr_len)
```

이걸 쪼개면:

| 부분 | 내용 | 읽는 법 |
|------|------|--------|
| **반환형** | `int` | 이 함수는 끝나면 정수(int) 하나를 돌려준다 |
| **이름** | `kprobe__tcp_v4_connect` | 함수 이름 |
| **인자 1** | `struct pt_regs *ctx` | "레지스터 정보"를 가리키는 포인터 ctx |
| **인자 2** | `void *sk` | **아무 타입이나** 가리키는 주소 sk |
| **인자 3** | `struct sockaddr *uaddr` | 소켓 주소를 가리키는 포인터 uaddr |
| **인자 4** | `int addr_len` | 정수 addr_len |

```python
# 파이썬으로 비유하면
def kprobe__tcp_v4_connect(ctx, sk, uaddr, addr_len):
    ...
    return 0   # C 는 "정수를 반환한다(int)"고 미리 약속
```

**`void *`(보이드 포인터)** 란? "타입을 안 정한, **그냥 어떤 메모리의 주소**"입니다. "안에 뭐가 있는진 모르지만 위치는 안다"는 뜻. 위 코드에선 `sk` 의 내용을 안 쓸 거라서 일부러 `void *` 로 받았습니다.

> 👉 **강의에서:** 10주차 `tcpconnect.c` 의 함수 첫 줄이 바로 이 형태입니다. 9주차 `workload.c` 의 `int main(int argc, char **argv)` 도 "정수를 반환하고, 인자 2개를 받는 함수"로 똑같이 읽으면 됩니다.

## 8. 파일 디스크립터와 `read` 시그니처 — "번호표·받을 공간·바이트 수"

리눅스에서 파일을 열면 **번호표(정수)** 를 하나 줍니다. 이걸 **파일 디스크립터(fd, file descriptor)** 라고 해요. 이후엔 "그 번호표"로 파일을 읽고 씁니다.

```c
long fd = syscall(SYS_openat, AT_FDCWD, "/dev/zero", O_RDONLY);  // 파일 열기 → 번호표 받음
if (fd >= 0) {                         // 0 이상이면 정상적으로 열림
    syscall(SYS_read, fd, buf, (size_t)1);   // 그 번호표로 1바이트 읽기
    syscall(SYS_close, fd);                  // 다 썼으면 번호표 반납(닫기)
}
```

`read(fd, buf, n)` 의 세 인자:

| 인자 | 비유 | 뜻 |
|------|------|----|
| `fd` | **번호표** | 어느 파일에서 읽을지 (파일 디스크립터) |
| `buf` | **받아올 빈 그릇** | 읽은 데이터를 담을 **메모리 공간의 주소(포인터)** |
| `n` | **몇 숟갈** | 몇 **바이트** 읽을지 |

`buf` 가 포인터인 이유: read 는 "읽은 데이터를 **이 주소(그릇)에 갖다 놓아라**" 라고 메모리 위치를 받아야 하니까요(3번 포인터 내용과 연결).

```c
char buf[1];   // 1바이트짜리 그릇 마련. buf 는 그 그릇의 시작 주소처럼 동작
```

> 👉 **강의에서:** 2주차(시스템콜이 무엇인가)와 9주차 `workload.c` 의 `syscall(SYS_read, fd, buf, ...)`, `syscall(SYS_openat, ...)`, `syscall(SYS_close, fd)` 에서 fd·buf·바이트수 패턴이 그대로 나옵니다.

## 9. "코드를 못 읽어도 괜찮다" — 1학년을 위한 우회로

> [!IMPORTANT]
> **C 코드가 한눈에 안 들어와도 전혀 문제없습니다.** 1학년이 이 강의에서 진짜로 가져갈 것은 **"개념"** 이지 "C 문법 암기"가 아닙니다.

코드를 만났을 때 이렇게만 하세요.

1. **굵은 글씨로 된 핵심 메시지**와 주석(`//` 뒤의 한국어 설명)만 따라 읽으세요. 그게 "이 코드가 무슨 일을 하는지"입니다.
2. `>> 32`, `*val`, `&x`, `struct ... {}`, `(타입 *)` 같은 기호가 나오면 **이 부록의 해당 항목 한 줄 요약**만 떠올리면 충분합니다.
3. 한 줄 한 줄 완벽히 해석하려 애쓰지 마세요. **"이 함수는 PID 를 꺼내서, 시스템콜 횟수를 1 늘린다"** 정도의 큰 그림만 잡으면 9·10주차 목표 달성입니다.

C 를 직접 짜는 것은 이 과목의 목표가 아닙니다. **읽고 흐름을 이해하는 것**이 목표예요.

## 💡 한 장 요약

| 기호/문법 | 뜻 | 비유 |
|-----------|-----|------|
| `int x = 3;` | 타입을 정해 변수 선언 | "정수 상자를 만들어 3을 넣음" |
| `u32` / `u64` | 부호 없는 32비트(4바이트) / 64비트(8바이트) 정수 | "4칸짜리 / 8칸짜리 상자" |
| `;` `{}` | 문장 끝 / 묶음 | "마침표 / 괄호 묶음" |
| `&x` | x의 주소 | "x네 집 주소" |
| `*p` | p가 가리키는 값 | "그 집에 찾아가 안을 봄" |
| `(*val)++` | 가리키는 값을 1 증가 | "그 집 안의 숫자에 +1" |
| `if (!val)` | val 이 NULL(빈 주소)이면 | "주소가 빈칸이면 들어가지 마" |
| `struct T {...};` | 여러 값을 묶은 상자 정의 | "칸막이 있는 도시락통" |
| `key.tgid` / `sin->x` | 멤버 접근(값 / 포인터) | "도시락통의 한 칸 꺼내기" |
| `0xFFFFFFFF` | 16진수 (1이 32개) | "32비트 전부 켜짐" |
| `id >> 32` | 오른쪽 32칸 밀기 = 위쪽 32비트 꺼내기 | "두 칸 중 위 칸만 떼기" |
| `(타입 *)값` | 타입 캐스팅 | "다른 안경으로 같은 메모리 보기" |
| `void *` | 타입 없는 그냥 주소 | "내용 모르는 집 주소만 있음" |
| `int f(...)` | int 를 반환하는 함수 | "정수를 돌려주는 기계" |
| `fd` | 파일 디스크립터(번호표) | "열어둔 파일의 번호표" |
| `read(fd, buf, n)` | fd 에서 n바이트를 buf 에 읽기 | "번호표 파일에서 그릇에 n숟갈" |
